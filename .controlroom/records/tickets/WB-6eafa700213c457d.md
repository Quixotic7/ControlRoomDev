## Backlog refinement

Prepared by Codex backlog refinement. This describes planned work; implementation has not started.

### Intended outcome

Keep a growing project understandable while retaining completed work, decisions, and historical context for humans and agents.

### Scope and approach

Start with a bounded design/discovery task: evaluate existing archive, filters, saved views, and parent grouping on a realistically crowded board; propose an explicit ticket lifecycle and focused follow-up changes. Use Concept for raw ideas, microtasks for small steps, and parent tickets for larger outcomes. Do not automatically delete or archive records as part of this investigation.

### Acceptance criteria

- [ ] Document the distinct sources of clutter: raw ideas, tiny tasks, duplicates, completed work, and large expanded parent groups.
- [ ] Demonstrate proposed default/focus/archive views with a representative fixture, showing how to find active work and retrieve older tickets.
- [ ] Specify explicit archive/unarchive behavior and any suggested bulk or completion-age controls, preserving links and discoverability.
- [ ] Check that decisions and UI rules remain available after their originating tickets are archived.
- [ ] Measure current board/search behavior on a documented large fixture and propose performance work only where measured behavior warrants it.
- [ ] Produce a reviewable recommendation with tradeoffs and a small ordered set of follow-up scopes; capture any unresolved product choices for human review.

### Implementation notes and related work

Inspect web/model.ts filters/grouping, web/ProjectPage.tsx saved views, and src/store.ts record/index/context behavior. Existing archive and is:archived filtering are starting points. Related: #17 bulk actions, #20 microtasks, #21 planning and #25 feed.

### Human review / verification

Walk through capturing an idea, promoting it, completing work, archiving/retrieving it, and finding a related decision on the representative board. Review the recommendation before scheduling implementation follow-ups.
