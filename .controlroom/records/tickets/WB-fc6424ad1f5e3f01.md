Found in the first real managed run on JuiceLab (run-2cbbea46973aebd1, ticket #35, worker Sonnet, 2026-10-01).
This blocks every Claude run (work, plan, review): the process exits before it starts.

## Problem
The run went queued → waiting_input within seconds with "Agent exited 1". The local log
(`.controlroom/.local/orchestration/run-2cbbea46973aebd1/agent.log`) holds one line:

    Error: --json-schema is not a valid JSON Schema: no schema with key or ref "https://json-schema.org/draft/2020-12/schema"

## Cause
`src/orchestration.ts` builds the result schema with `z.toJSONSchema(...)`, which emits
`"$schema":"https://json-schema.org/draft/2020-12/schema"`. Claude Code 2.1.284 (`claude -p --json-schema …`)
rejects a schema that declares that meta-schema. The fixture harness in the tests does not validate the schema,
so the suite cannot see this.

## Reproduction (outside Control Room, a few cents of Haiku)
    echo "Reply with outcome ready." | claude -p --output-format json --max-turns 2 --permission-mode plan \
      --model claude-haiku-4-5-20251001 --json-schema '{"$schema":"https://json-schema.org/draft/2020-12/schema","type":"object","properties":{"outcome":{"type":"string"}},"required":["outcome"],"additionalProperties":false}'
    → Error: --json-schema is not a valid JSON Schema: no schema with key or ref "https://json-schema.org/draft/2020-12/schema"

The same schema without the `$schema` key is accepted and `structured_output` comes back (checked the same way).

## Wanted
- Remove `$schema` from the schema passed to Claude (and check whether anything else `z.toJSONSchema` emits by
  default is unsupported by the CLI, e.g. by generating draft-07).
- A guarded native smoke check (opt-in, since it spends provider usage): launch the configured Claude profile
  with the real schema and a one-line prompt, and report whether a structured result came back. Offer it on the
  Agents page ("Test this profile") so a human can find this class of failure before delegating work.
- When a provider process exits non-zero before its first event, put the first lines of its stderr into the
  "Managed run needs you" question (bounded and redacted), so the cause is visible without opening the local log.

## Acceptance criteria
- With Claude Code 2.1.284, a managed Claude work run on JuiceLab starts, and returns a structured result.
- The run's question on failure shows the provider's error line.
