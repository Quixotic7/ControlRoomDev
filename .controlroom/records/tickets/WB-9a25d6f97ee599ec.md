### Intended outcome

Track small steps inside a ticket with a checklist, without creating separate numbered tickets or cluttering the board.

### Scope and approach

Provide an editable Microtasks section with add, rename, reorder, complete, and remove actions. Keep it readable/editable in Markdown and include it in agent context. Reuse Markdown task-list syntax in a clearly owned section where practical; preserve other prose and existing acceptance criteria.

### Acceptance criteria

- [ ] Enter adds a nonblank checklist item and keeps focus ready for the next; items can be checked, edited, reordered, and removed with keyboard alternatives.
- [ ] Items persist across save/reopen and direct Markdown edits; concurrent changes use revision protection.
- [ ] Agents can read and update checklist state through the supported record interfaces without creating ticket IDs for checklist items.
- [ ] The ticket displays completed/total counts, including the all-complete state; cards may show a compact count without listing every item.
- [ ] Completing the checklist does not automatically move the ticket to Done or claim its acceptance criteria are satisfied.
- [ ] Unrelated Markdown, attachments, and comments survive checklist edits.

### Implementation notes and related work

Start with web/RecordDetail.tsx, web/RecordMarkdown.tsx (GFM rendering already exists), src/files.ts Markdown preservation and src/store.ts context. Related: #14 for work large enough to need child tickets; #23 for reducing board clutter.

### Human review / verification
