## Backlog refinement

Prepared by Codex backlog refinement. This describes planned work; implementation has not started.

### Intended outcome

When a human opens a ticket in Review, make Accept into Done and Request changes immediately available without changing a status dropdown.

### Scope and approach

Add prominent, distinct review outcome buttons in ticket detail, alongside the review summary and conversation. Request changes should target the configured Failed Review column when available; otherwise use an explicit project setting or visible choice of an appropriate progress column. Keep naming aligned with the board actions in #16.

### Acceptance criteria

- [ ] For a Review ticket, a human sees Accept into Done and Request changes with the destination clearly indicated; these do not appear as active agent acceptance actions.
- [ ] Accept into Done saves any pending ticket edits and moves to the configured Done destination using current revision checks.
- [ ] Request changes allows a concise review comment, saves it as human Review feedback, and moves the ticket to the configured return stage; submitting does not require a long questionnaire.
- [ ] If a save or transition fails, the ticket remains open with the draft/feedback retained and a clear error; retry does not duplicate feedback.
- [ ] A successful action closes the dialog consistently with Save and updates the board immediately, retaining previous handoff and verification history.
- [ ] Multiple custom Review/Done/progress columns are handled by explicit deterministic destination rules, and accepting a parent never silently accepts its children.

### Implementation notes and related work

Start with web/RecordDetail.tsx save/close/review actions, src/store.ts authority/history, and project column configuration. Related: #16 provides quick actions outside the dialog; #18 handles status customization. Share action logic to avoid divergent validation.

### Human review / verification

Open a reviewed ticket, accept it and observe the board; repeat with Request changes and a comment. Test pending edits, a stale save, renamed columns, and missing Failed Review configuration. Check attribution and preservation of the review conversation.
