Requested by the JuiceLab coordinator (JuiceLab board #33, owner asked for Control Room tickets in chat, 2026-10-01).

## Problem

`orchestrationSchema` caps `maxTurns` at 100 and `timeoutMinutes` at 180, for every profile and every ticket. A
JuiceLab engineering ticket routinely needs more: a release build is about 10 minutes, the native UI suite about
15, sanitizer runs several minutes each, and an engine ticket takes well over 100 tool turns. The verification
command shares the same timeout.

## Wanted

- Higher caps (suggest 1000 turns, 12 hours), with the current defaults unchanged.
- Limits per worker profile, and a separate timeout for the verification command.
- When a run hits a limit with work in its checkout, the run is resumable in the same checkout and session
  (not a fresh attempt that starts over), and the limit that was hit is named in the run's state.

## Acceptance criteria

- A profile configured with 400 turns and a 6 hour limit is accepted and enforced.
- A run stopped by its turn limit can be resumed by the orchestrator or a human and continues from its checkout.
