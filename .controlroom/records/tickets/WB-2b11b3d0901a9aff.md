## Backlog refinement

Prepared by Codex backlog refinement. This describes planned work; implementation has not started.

### Intended outcome

Show the prospective ticket order while dragging so the user knows where the ticket will land before releasing it.

### Scope and approach

Add a stable insertion preview or displaced-row/card preview to existing board and table reordering. Keep the preview local until drop and share the behavior with the planning view in #21.

### Acceptance criteria

- [ ] While dragging over reorderable tickets, a clear insertion position updates before mouse release, including above the first and below the last item.
- [ ] Moving between valid positions updates the preview without flicker or repeatedly writing record order.
- [ ] Escape, dropping outside a valid target, and canceled drags restore the original visual order without persisted changes.
- [ ] A successful drop persists the displayed placement; failed/stale saves restore or reconcile the list and show an error.
- [ ] Scrolling during a drag keeps the preview aligned; invalid cross-parent/status operations follow existing explicit rules.
- [ ] Keyboard reorder controls remain available, and reduced-motion settings avoid unnecessary movement.

### Implementation notes and related work

Start with web/BoardView.tsx, web/TableView.tsx, web/TicketCard.tsx and web/ProjectPage.tsx drag/drop handlers; style in web/project.css. Related: #21, but this fixes the existing reorder interaction independently.

### Human review / verification

Observe a drag before release, cancel it, reorder at both ends, and repeat in a long scrollable list. Confirm canceled previews produce no record writes and the saved order matches the preview.
