Found while checking #78/#80 from the JuiceLab board (Claude Fable, 2026-10-01).

## Problem
`controlroom agents propose --file CONFIG_JSON --brief-file MARKDOWN` silently drops the brief. The proposal is
staged without `workerBrief`, the human applies it, and `.controlroom/agents/worker-brief.md` is never written.
No error or warning is shown.

## Cause
`src/client.ts`: `parseArgs` only reads a value for options listed in `valueOptions`. `--brief-file` is not in
that set, so it is recorded as a bare flag, `option("brief-file")` returns undefined, and the path becomes a
stray positional argument. `src/cli.ts` (`agents propose`) therefore never adds `workerBrief` to the request.
The server, store and MCP paths look right; the tests cover those, not the CLI flag.

## Evidence
JuiceLab board: three proposals staged with `--brief-file` (agent-proposal-55cb49ec…, d5094938…, e086cff7…);
none of the stored records has a `workerBrief` key; after the owner applied e086cff7, `agents status` shows
`workerBrief.content` empty and `.controlroom/agents/` does not exist.

## Wanted
- Add `--brief-file` to `valueOptions` (and check the other documented value flags against that list).
- A CLI-level test that `agents propose --brief-file` stores the brief in the proposal.
- Better: make `parseArgs` fail on an unknown `--option` or on leftover positionals for commands that take none,
  so a mistyped or unregistered flag cannot be dropped silently.

## Acceptance criteria
- A proposal staged through the CLI with `--brief-file` shows the brief in its diff and writes
  `.controlroom/agents/worker-brief.md` when applied.
- An unregistered `--flag value` is an error, not a silent no-op.
