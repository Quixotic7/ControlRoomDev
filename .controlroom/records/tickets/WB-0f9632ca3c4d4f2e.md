## Backlog refinement

Prepared by Codex backlog refinement. This describes planned work; implementation has not started. Proposed behavior remains subject to human scope review.

### Intended outcome

Click Save to ticket, enter a short ticket title in a focused prompt, and immediately open the created ticket in the centered detail popup to add further details. Preserve the screenshot and annotations throughout. Source: screenshot annotation A1 (note-d0faa9fc-2c69-47fb-961e-0cb7aaaba320).

### Scope and approach

For the single-new-ticket path, make Save to ticket open a small in-app title dialog instead of silently creating a generically named ticket. Prefill from any title already entered, select/focus the text for quick replacement, and support Enter to create and Escape/Cancel to return to the annotation editor. Require a nonblank trimmed title; no additional questionnaire.

After saving the annotations and creating the ticket successfully, use the returned ticket ID to open its normal detail dialog. The title prompt is the single authoritative title entry; remove or synchronize the existing inline title field to avoid competing values. Keep attachment-to-existing-ticket and split-annotation workflows distinct, without introducing a single-title prompt into those paths. New tickets use the project's normal initial stage, currently Concept.

### Acceptance criteria

- [ ] Save to ticket in new-ticket mode opens an accessible, focused title prompt before creating a ticket. Typing a title and pressing Enter creates it; whitespace-only input is rejected inline.
- [ ] Cancel/Escape creates no ticket, returns focus to the editor, and preserves the screenshot and unsaved annotation draft.
- [ ] On success, the editor/title prompt hands off to the centered detail popup for the exact newly created ticket. Its heading matches the entered title and the ticket URL identifies it.
- [ ] The description contains the screenshot preview and written annotation instructions with stable annotation references. Base image, editable geometry and attachment links remain intact and available to agent context.
- [ ] The user can add description/details immediately. Save or clicking outside uses existing save-and-close behavior; a failed save retains the draft and explains the error.
- [ ] While submission is pending, repeated clicks/Enter cannot create multiple tickets. Annotation-save or creation failures retain the title and annotations, show a useful error, and do not claim success.
- [ ] Once creation succeeds, a later refresh/navigation failure offers reopening the returned ticket rather than creating another. Uncertain write results are not automatically replayed.
- [ ] Saving a standalone screenshot still creates no ticket. Attaching to an existing ticket and splitting annotations retain their current explicitly selected destinations and behavior.
- [ ] Keyboard focus transfers correctly between editor, title prompt and ticket detail, including on narrow screens; there is no inaccessible stack of active modal dialogs.
