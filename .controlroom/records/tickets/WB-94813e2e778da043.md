Seen on JuiceLab #35 (2026-10-01, run-6421166cb545a54e). The owner answered both managed-run questions with a reply ('Seems good'). The replies were stored as ordinary comments, the question comments stayed resolved=false, and the run stayed in waiting_input, so from the owner's side 'I answered' looked like it should have retried the run. The question text does say 'resolve this question to retry', but the reply box is the obvious control.

Wanted: on a managed-run question, make the action explicit where the human answers: 'Answer and retry' (resolves and resumes), 'Answer only', 'Stop run'. Show the run's state next to the question after answering (retrying / still waiting), and say in Needs you when an answered question is still unresolved.

Acceptance: answering a managed-run question with the default action resumes the run; an answered-but-unresolved question is visibly still open.
