## Backlog refinement

Prepared by Codex backlog refinement. This describes planned work; implementation has not started.

### Intended outcome

Make in-progress work easier to monitor with restrained animation, elapsed time, and agent-reported progress that clearly communicates uncertainty.

### Scope and approach

Show current owner/claim, last reported update, elapsed time since entering In Progress, and an optional agent-reported percentage or checklist progress. Elapsed wall-clock time is not measured active work. Running-agent supervision remains outside the initial product; animation must not imply a verified live process.

### Acceptance criteria

- [ ] Cards/rows and ticket details show last reported activity and elapsed time with explicit labels; reload reconstructs elapsed time from durable timestamps.
- [ ] Agents can report a short progress note and optional bounded percentage through CLI/MCP; percentages are labeled estimates, and missing values display as unknown rather than invented.
- [ ] Checklist completion, if shown from #20, is labeled separately from overall completion; 100% never automatically moves a ticket to Done.
- [ ] Expired claims, stale reports, and blockers are visibly distinct from recent reported activity; the UI never treats a claim alone as proof an agent is running.
- [ ] Subtle in-progress animation respects reduced-motion preferences and stops or changes appropriately for blocked/stale/review/done states.
- [ ] Repeated work sessions retain useful history; displayed elapsed duration uses a documented rule for leaving and re-entering In Progress, without double-counting or inventing active hours.

### Implementation notes and related work

Start with web/TicketCard.tsx, web/TableView.tsx, src/types.ts, src/store.ts claims/history and CLI/MCP update interfaces. Prefer explicit reported data and disposable derived timers over writing a record every second. Related: #20 and #25.

### Human review / verification

Exercise a fresh report, missing estimate, stale/expired claim, blocker, and re-entry into In Progress with controlled timestamps. Reload and enable reduced motion; verify the labels never claim measured agent runtime.
