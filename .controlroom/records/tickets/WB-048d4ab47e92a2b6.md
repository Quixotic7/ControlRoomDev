## Finding

runVerification converts a null process status to exit code 0 when result.error is absent. A command killed by a signal can therefore be submitted as successful verification and shown as passing in the ticket.

## Reproduction and evidence

In a disposable test, runVerification("kill -TERM $$", temporaryDirectory) returned exitCode: 0 with empty output. The command terminates only its own spawned shell; no application service was affected.

## Acceptance criteria

- [ ] Only an actual normal zero exit is recorded as a pass.
- [ ] Signal termination, timeout, and spawn errors produce failure evidence with a useful diagnostic.
- [ ] Both CLI and MCP reject failed verification unless the existing explicit failure override is used; overridden evidence remains visibly failed.
- [ ] Add focused tests for successful exit, nonzero exit, and signal termination.
