## Choice

Name the local authentication cookie with the stable project ID. Each project keeps its existing token and loopback service.

## Context and rationale

Browser cookies are shared across ports on the same host. The previous common cookie name let opening a second Control Room project overwrite the first project’s session. Both Control Room Dev and JuiceLab run on 127.0.0.1.

## Alternatives and tradeoffs

Separate hostnames require more local setup; storing a bearer token in browser JavaScript would change the security model. Project-specific HttpOnly cookies preserve the existing model and allow concurrent projects. A refresh establishes the new cookie after an upgrade. Tokens are still checked by each service; attribution labels do not become a security boundary.
