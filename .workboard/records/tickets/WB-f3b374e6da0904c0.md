## Finding

The stdio request loop awaits each tool call before reading the next request. A long wait_for_update blocks unrelated reads, claim renewals, pings, and cancellation notifications on the same connection until it finishes.

## Reproduction and evidence

Against a disposable board, sent wait_for_update followed by get_ticket. The lookup remained unanswered while waiting; both responses arrived only after a comment released the wait.

## Acceptance criteria

- [ ] Dispatch independent MCP requests without blocking the input reader and correlate each response with its request ID.
- [ ] get_ticket and ping respond while a wait_for_update request remains pending.
- [ ] Handle cancellation and connection closure so pending waits clean up their event streams and timers.
- [ ] Keep coordinated mutations serialized by the existing shared service and add concurrent-request regression coverage.
