## Backlog refinement

Prepared by Codex backlog refinement. This describes planned work; implementation has not started.

### Intended outcome

Select multiple tickets and change shared fields in one operation, with predictable selection and a clear result for every ticket.

### Scope and approach

Extend the existing table checkbox/bulk-status UI to status, priority, owner, labels, and parent; expose selection on the board as well. Labels need separate add/remove actions so existing labels are not accidentally replaced. Approval actions are specified in #16; deletion is outside this ticket.

### Acceptance criteria

- [ ] Board and table support explicit multi-selection, select visible items, clear selection, and a persistent count while the action is being prepared.
- [ ] Only selected visible tickets are affected; filtering or changing view reconciles selection and never silently includes hidden items.
- [ ] Mixed values display as Mixed. Fields left unchanged retain their original values; label addition/removal preserves all other labels.
- [ ] Each change uses the ticket’s revision and normal validation, including parent cycles, scope, and review evidence requirements.
- [ ] The result identifies succeeded, failed, and unchanged tickets; failed items remain available for correction/retry without reapplying successful writes.
- [ ] Selection and operations are keyboard accessible and survive ordinary live refresh without jumping to different tickets.

### Implementation notes and related work

web/TableView.tsx currently loops onMove for bulk status changes. Start there and in web/ProjectPage.tsx; coordinate shared selection/results rather than creating a second independent bulk model. Related: #16 and #23.

### Human review / verification

Bulk-edit a mixed selection, add/remove labels, and simulate a stale revision plus a validation failure. Verify exact affected IDs, preservation of untouched fields, and per-item feedback.
