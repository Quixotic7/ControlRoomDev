## Backlog refinement

Prepared by Codex backlog refinement. This describes planned work; implementation has not started.

### Intended outcome

Make decision documentation a routine part of the agent protocol so consequential project choices and their reasoning are retained beyond the originating ticket.

### Scope and approach

Update tool-neutral agent guidance, generated context, and MCP onboarding to instruct agents to look up existing decisions and create/update decision records when choosing a meaningful architecture, product behavior, UI convention, dependency strategy, or workflow policy. Keep routine implementation trivia out of the decision log.

### Acceptance criteria

- [ ] Instructions state when to record a decision, with examples of consequential choices versus minor implementation details.
- [ ] A decision records the choice, context, rationale, alternatives considered, tradeoffs, scope, attribution, and links to relevant tickets/references.
- [ ] Agents search existing decisions before creating another, link tickets to the applicable decision, and supersede earlier decisions explicitly rather than rewriting away the old rationale.
- [ ] Unresolved proposals and assumptions are labeled as such; an agent does not invent human agreement or treat an unresolved question as an accepted choice.
- [ ] Agents may record decisions within approved work, but decision records do not grant implementation scope approval or bypass human acceptance of tickets.
- [ ] Review handoffs identify decisions made or changed, and agents can retrieve those records after the originating ticket is archived.
- [ ] The instructions ship consistently in AGENT_GUIDE.md, generated context, and MCP guidance; users can see the rule in the playbook from #26.

### Implementation notes and related work

Start with AGENT_GUIDE.md, src/store.ts contextMarkdown and decision validation, src/mcp.ts onboarding/list_knowledge, and existing record create/update APIs. Reuse durable decision records and predecessor links. This is protocol-driven behavior, not automatic inference from arbitrary file changes.

### Human review / verification

Run a disposable agent workflow that makes a meaningful design choice, records its alternatives/rationale, links it to the ticket, and later supersedes it. Confirm the guidance is available through CLI/MCP context and that archived work does not hide its decisions.
