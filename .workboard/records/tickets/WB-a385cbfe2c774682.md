## Backlog refinement

Prepared by Codex backlog refinement. This describes planned work; implementation has not started.

### Intended outcome

Break down a parent ticket into real child tickets directly inside its detail dialog, using a title field and Enter for each child. Keep the parent open and the input ready for the next title.

### Scope and approach

Add a Children section with quick entry and links to existing children. Use the project’s configured intake/backlog default and show the destination. For a new unsaved parent, save it successfully before persisting children; retain pending titles if that save fails. Checklist items are handled separately in #20.

### Acceptance criteria

- [ ] Entering a nonblank title and pressing Enter creates one numbered ticket with the current ticket as its parent; no questionnaire is required.
- [ ] Repeated entry retains focus and supports several children without closing the parent; whitespace and repeated submission while saving do not create duplicates.
- [ ] The child appears immediately in the Children section and under its parent on a parent-grouped board.
- [ ] Creation failures retain the title and give a retryable error. Closing the parent follows existing save behavior.
- [ ] Child creation preserves agent scope rules, and completing children never automatically completes the parent.

### Implementation notes and related work

Start with web/RecordDetail.tsx (existing child list), web/QuickTicket.tsx, and src/store.ts create/relationship validation. Reuse quick entry; coordinate the parent chooser with #15.

### Human review / verification

Create several children from an existing parent and from a newly drafted parent. Open a child, reload, and confirm its title, number, parent, and stage. Exercise a failed save and keyboard-only entry.
