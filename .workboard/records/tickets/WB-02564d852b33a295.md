## Backlog refinement

Prepared by Codex backlog refinement. This describes planned work; implementation has not started.

### Intended outcome

Make workflow status customization easy to discover from the board and safe to use as the project evolves.

### Scope and approach

Settings already supports naming, roles, ordering, addition, and removal of columns. Expose a clear Customize statuses entry from the board and improve that existing editor. Retain stable IDs and explain why workflow roles control agent behavior; multiple columns can share a role, as Concept and Backlog do here.

### Acceptance criteria

- [ ] A user can find status customization from the board, add a status, rename it, and change its order without editing configuration files.
- [ ] Renaming or reordering retains ticket associations, history, and saved views; refreshing preserves the configuration.
- [ ] The editor distinguishes display name from workflow role and validates required roles and invalid/blank names.
- [ ] Removing a populated status offers an explicit destination/migration flow or a clear route to move its tickets first; no tickets are orphaned.
- [ ] Where a role has multiple columns, default destinations for new tickets and agent role-based moves are visible and deterministic.
- [ ] Concurrent configuration changes cause reconciliation feedback rather than silent overwrites.

### Implementation notes and related work

Start with web/Settings.tsx, web/ProjectPage.tsx, src/store.ts updateConfig and role-to-column lookups in src/cli.ts/src/mcp.ts. Extend existing configuration rather than introducing competing status data.

### Human review / verification

Add and rename a status, reorder it, reload, and remove an empty status. Exercise removal with tickets and ambiguous role destinations using Concept/Backlog and In Progress/Failed Review.
